# Repository Guidelines

## Project Structure & Module Organization

This is a personal GitHub profile README repository. The main content lives in `README.md`, which mixes Markdown and inline HTML for layout, images, badges, and profile sections.

- `README.md`: primary profile page content shown on GitHub.
- `images/`: local visual assets referenced by the README, currently `banner.png` and `profile.gif`.
- `.github/workflows/snake.yml`: GitHub Actions workflow that generates `snake.svg` into the `output` branch.

Keep personal profile content changes in `README.md`. Add static assets under `images/` and reference them with relative paths such as `images/example.png`.

## Build, Test, and Development Commands

There is no application build step or package manager configuration in this repository.

- `git status --short`: check changed files before committing.
- `git diff -- README.md AGENTS.md`: review documentation edits.
- `git log --oneline -8`: inspect recent commit style.

Preview README changes on GitHub or with a Markdown previewer that supports inline HTML. The snake animation is generated by GitHub Actions, not a local script.

## Coding Style & Naming Conventions

Use concise Markdown headings and keep inline HTML where it controls GitHub layout. Prefer relative asset links, for example `<img src="images/banner.png">`.

For new image assets, use lowercase descriptive names with hyphens, such as `images/project-preview.png`. Avoid renaming existing assets unless all README references are updated.

Indent nested HTML consistently with two or four spaces, matching the surrounding block. Keep badge and icon `alt` text descriptive.

## Testing Guidelines

No automated tests are configured. Validate changes by checking:

- Local asset paths resolve correctly from `README.md`.
- External badge, icon, and animation URLs still load.
- Markdown and inline HTML render correctly on GitHub.
- `.github/workflows/snake.yml` remains valid YAML after edits.

For workflow changes, test with `workflow_dispatch` after pushing to a branch with Actions enabled.

## Commit & Pull Request Guidelines

Recent commits use short messages such as `fix image` and `fix: fix image links`. Prefer concise imperative messages, with a scoped prefix when helpful, for example `docs: update profile intro`.

Pull requests should summarize visible profile changes, list added or changed assets, and include screenshots when rendering changes. Link related issues when applicable and note whether the snake workflow is affected.

## Agent-Specific Instructions

Do not edit generated files on the `output` branch from this working tree. Update the workflow or README source instead. Preserve user-authored wording unless asked to copy edit.
